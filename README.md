# Dynamic CLM (DynCLM)

## Introduction

Agent sessions on Apple Silicon fill the context window with obsolete tool dumps and stale drafts. Reclaim that **rewrites and re-prefills every turn** is especially expensive when **memory bandwidth** is the limit - a common reason people call CLM a poor fit for Mac. This repo measures that tradeoff on the local stack below (**M5 Max** + oMLX today; **M5 Pro** / base **M5** profiles still open): either CLM is usable there, or **DynCLM**'s calibrated **hardware profile** (`ρ`) can defer reclaim until rewrite cost is worth paying.

**CLM** soft-marks stale spans and physically rewrites on every turn that has dead text - correct selective reclaim, paid as rewrite/re-prefill each time. **DynCLM** keeps the same mark → drop → verbatim-survivors methodology, but marks internally and **defers** the physical rewrite until a cost model says budget/memory pressure warrants a batch. Where per-turn rewrite is expensive, that should cut rewrite load while matching CLM on selective-ignore quality canaries.

Method + math: **[docs/method.md](docs/method.md)**. Live proof attempt: **[docs/report.md](docs/report.md)**.

**Naming:** Spell out "Dynamic CLM" or use **DynCLM** in writeups. Do not abbreviate as DCLM (that name is taken by DataComp-LM).

## Local stack

- Hardware: Apple M5 Max (ship evidence today; M5 Pro / base M5 hardware profiles still open)
- Server: [oMLX](http://127.0.0.1:8000) (OpenAI-compatible)
- Gate baseline model: `Qwen3.8-27B-4bit`

Set `OMLX_API_KEY` (or rely on `~/.omlx/settings.json`).

## Protocols at a glance

| | Summarize compact | CLM | DynCLM |
|---|---|---|---|
| Reclaim | Lossy `[CONTEXT_SUMMARY]` when over window | Soft-ignore + rewrite every edit | Soft-ignore + **batched** rewrite |
| Survivors | Paraphrase + recent raw | Verbatim live spans | Verbatim live spans |

Full comparison and how markers/rewrites work: [docs/method.md](docs/method.md).

## Phases (DynCLM)

1. **Append**: normal operation; prefix cache preserved.
2. **Soft invalidation**: append `<<<DYNCLM_IGNORE ...>>>` markers; still append-only.
3. **Deferred rewrite**: one batched physical rewrite when the cost model fires (same drop as CLM).
